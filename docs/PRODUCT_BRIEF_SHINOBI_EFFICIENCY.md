## 0. 一页纸结论

**核心主张**：Shinobi 的提效，不是"让开发者写得更快"，而是 **把"人的在线时长"从交付关键路径上拿下来**。

**三条杠杆**

| # | 杠杆 | 作用 | 现状 |
|---|---|---|---|
| 1 | 无人值守推进 | 人离线，任务不下线 | ⚠️ 局部可用，跨端未打通 |
| 2 | 并行轨道 | 同一需求的多个方案并行验证 | ✅ 可用（同机多 Agent） |
| 3 | 沟通成本压缩 | 替身基于私有记忆回答模块级问题 | ⚠️ 记忆已持久化，质量不可观测 |

**一个天花板**：人的**连续上下文窗口**。审阅与拍板是最终瓶颈——Agent 产出扩大 N 倍而决策带宽不变，净效果是待办积压，不是提效。

**一个判据**：**可替代度 ≈ 1 / 人工验证成本**。机器可判的（编译 / 测试 / lint）可全自动；不可逆承诺（排期 / 发布）不可外包。

**必须诚实告知的一句话**：

> 「离线替身答疑」——即产品定义中的核心价值场景——**当前尚未落地**。宿主侧入站订阅缺失，且被显式禁止自主拉起。首期必须补齐，否则该场景退化为"问自己的替身"，净价值为零。

## 1. 问题定义：研发交付的三个时间黑洞

| 黑洞 | 具体表现 | 成本归属 |
|---|---|---|
| **串行等待** | 等评审、等环境、等队友答复；人不在链路上，任务也不能动 | 直接吃掉交付周期 |
| **信息搬运** | 同一模块的"为什么这么设计""上次踩过什么坑"被反复解释 | 资深者的注意力被稀释 |
| **上下文重建** | 跨人、跨时段接手时重建业务暗语与工程约束 | 新人上手周期长，外包/轮岗成本高 |

**共同特征**：三者都不产生代码，却都占用关键资源——**人的在线时长**。

## 2. 价值模型

### 2.1 三个杠杆的收益性质不同

- **杠杆 1（无人值守）**：收益来自"串行等待"被改写为后台并行推进。**前提是可机器验证**——凡能自动证伪的工作才吃得到这份红利。
- **杠杆 2（并行轨道）**：收益来自方案探索的并行化，人从"串行试错"上移到"收敛决策"。
- **杠杆 3（沟通成本压缩）**：收益来自私有记忆的复用。这是**唯一不改变现有研发流程**就能见效的一条。

### 2.2 天花板：L2 类产出的并发上限

方案取舍、架构权衡这类工作（下表 L2）有一个被普遍忽略的隐藏成本：**人必须处于上下文里**。这类产出无法靠堆 Agent 提升吞吐——它的上限就是人类可投入的连续上下文时间。

> **结论：L2 的吞吐上限，就是整个提效方案的上限。** 任何绕过它的设计都只是在制造积压。

### 2.3 准入分级（L0–L3）：从"感觉排序"到"可判定门槛"

| 级别 | 验证方式 | 人工验证成本 | 失败可回滚 | 准入策略 |
|---|---|---|---|---|
| **L0 机器可判** | 编译 / 测试 / 类型检查 / lint | ≈ 0 | 是 | ✅ 可全自动，无需人工确认 |
| **L1 可引用证据** | 代码路径 / commit / 日志 / 记忆出处 | ~10s / 条 | 是 | ✅ 附证据即可采信 |
| **L2 需上下文复核** | 方案取舍 / 架构权衡 | 10–30min / 条，且人须在上下文 | 是 | ⚠️ 替身出观点，人决策 |
| **L3 不可逆承诺** | 排期 / 发布 / 对外沟通 | = 责任本身 | **否** | ❌ 不外包 |

这张表的用途：它同时解释了**为什么技术支持能先落地**（大量落在 L0/L1）、**为什么排期必须排最后**（L3，不可回滚）。

### 2.4 场景成熟度分级

| 场景 | 判断 | 理由 | 现阶段动作 |
|---|---|---|---|
| **技术支持** | 🟢 现在就能拿下 | 异步、可中断、**答案可验证**（提问者自带 ground truth） | 优先做，作为首期试点 |
| **方案讨论** | 🟡 工程已就位，结论可信度未就位 | 治理机制过硬（轮数熔断、静默即成功、成员准入），缺的是对抗性与溯源 | 替身出观点 + 强制异见位 + 结论溯源 |
| **技术排期** | 🔴 不宜替代，降级为证据供给 | 排期是**历史数据拟合 + 承诺兑现**问题，不是推理题；且无 ground truth 可在试点周期内闭环验证 | 只出范围 / 依赖 / 风险清单与历史耗时分布 |

### 3.2 未具备 / 待下沉 ⚠️（关键缺口）

| 缺口 | 实测结论 | 影响 |
|---|---|---|
| **宿主侧入站订阅** | `nostr_relay_url` 为死字段（声明 + 赋值，从未被读取）；宿主机内无任何 relay 订阅任务 | **「替身替你答疑」不成立**——外部消息无法唤醒本机 Agent |
| **relay 总线未接通两端** | 前端亦无 relay 客户端（`src/` 内 `8080/relay/nostr` 命中全为展示文案）；`package.json` 无任何 Nostr 签名库；桌面包不依赖 server crate | relay 层目前是**装饰性**的；真实互通走 Tauri IPC + 本地 stdio |
| **服务端准入强制** | `relay.rs:46` 硬编码单房间 `"room-acp-dev"`，**无 per-room 订阅鉴权**；准入拦截实际在 `src/App.tsx`（前端） | 任何能连上 relay 的客户端都能向唯一房间发消息；**任何绕过 UI 的调用不受约束** |
| **自主唤醒被显式禁止** | `main.rs:100` 要求 Agent 必须由用户手动 Start，禁止程序自发拉起 | 有意的安全设计，但封闭了离线替身路径 |
| **记忆质量不可观测** | `acp_memories(id, category, key, content, created_at)` 无任何质量字段；且注释标注为「**不可清理资产**」 | 错误记忆**写入即终态**，会随每次召回复利放大，且比无记忆时更自信 |
| **ACP 事件非结构化** | `log_acp_event` 为 `format!` 纯文本 append 到 `logs/acp.log`，另有双写副本 | 无法按议题聚合，溯源链与执行态度量都无处落地 |
| **消息时间数据完整性** | 实证核查发现 `timestamp` 与消息 `id` 内嵌 epoch 存在不一致（抽样 91 条中 72 条不符，最大偏差 7.16 天） | **所有"决策延迟"类指标在修复前不可采信** |
| **准入校验函数未实现** | `validate_topic_agents_admission` 全仓仅存在于 TECH_SPEC 文档，源码零命中 | 该条**不可计入既有资产**（首期成本需上修） |

> **一句话总结第 3 节**：Shinobi 当前是**一台已经能跑、但还没接上外部世界的多 Agent 协作工作台**。它的核心叙事（离线替身）与当前实现之间，隔着一条明确且不长的链路——宿主侧入站订阅。

## 4. 落地路径

| 优先级 | 事项 | 依据 | 验证成本 |
|---|---|---|---|
| **P0-a** | relay 订阅鉴权 + per-room 路由（替换硬编码房间） | 安全前提：无鉴权的唤醒通道不可开放 | L2 |
| **P0-b** | 宿主侧入站订阅，**首期按"排队不唤醒"落地** | 技术支持的定义前提；不触碰 `main.rs:100` | L1 |
| **P0-c** | 结构化事件落 SQLite（一次改动同时满足"溯源链"与"执行态度量"） | 现为 append-only 文本，无法聚合 | L1 |
| **P0-d** | 聚合视图 + 只读健康度面板（基线量化） | 原料已在 `messages` 表，零采集链路 | L0（纯读） |
| **P0-e** | 脱敏 / 打包**下沉 Rust 侧**；只读**进程级**强制 | 现仅前端自律；只读应是默认姿态而非 UI 开关 | L1 |
| **P0-f** | `acp_memories` 增质量字段（`verified_by`/`feedback`/`last_used_at`）+ 引用回显 + 一键「不准」 | 记忆不可清理 ⇒ 必须可问责 | L1 |
| **P1** | 异见位（绑定可执行证伪路径）+ 跨厂模型位写入机制 | 打破同源相关性盲区 | L1 |
| **P1** | 排期降级为证据供给：历史耗时 / 返工 / 阻塞分布库 | 无责任风险，且是后续任何授权的前提 | L1 |
| **P2** | 待命唤醒授权（受控待命） | 需决策者拍板，默认关闭 | L2 |
| **P2** | 排期双轨制（盲写 + ≥30 闭环样本 + 事件阈值） | n<30 无统计意义 | L3 |
| **P2** | 远程 ACP dial-out（原 Phase 3） | 技术支持场景非必需 | L3 |

**顺序原则两条**

1. **鉴权先于订阅**：先开订阅、后补鉴权，中间窗口就是一条**无身份校验的远程唤醒通道**。
2. **P0-b 的落地形态**：首期只需"消息落库排队，等人回来批量处理"，**不需要**放开自主拉起授权。待命唤醒（P2）届时用影子期数据支撑决策。

## 5. 度量与验收（可证伪）

### 5.1 六项指标（合并为一套口径）

决策延迟 · 人工介入率 · 返工率 · 往返轮次 · 澄清问题数 · 平均等待时间

全部由 `messages`（讨论态）+ 结构化事件表（执行态）联合派生，**不新增采集链路**。

### 5.2 影子模式（首期验证方式）

**Agent 与人类并行给结论，只记录不执行**，跑 1–2 个月拿到准确率数据，再决定哪些环节可真正交付。

- 影子期**零权限风险**：不需要唤醒授权、不需要写盘、不进入决策材料。
- 影子期必须安排**真实的人工离场窗口**，否则测到的仍是"人在线"的链路。

### 5.3 分母完整性（三个必须写死的约束）

1. **三态区分**：`exec_status(ok|skipped|error)` 与 `completion_status(succeeded|failed)` 必须分列。平台运行记录中 `skipped` 会同时被标记为 `completionStatus=failed`——**若用后者当成功轴，一个完全健康的系统会算出 100% 失败率**（实测 307/307）。
2. **`skipped` 不计入失败分子**：它表示"本轮无事可做"，与"无监督推进失败"是两件事。
3. **关联键**：定时运行**不带 `runId`**，必须用 `(job_id, run_at_ms)` 复合键；议题/频道 ID 需由调用方以 `correlation_id` 注入。`cost_usd` 不在运行记录中，须由 token × 价目派生。

### 5.4 准入判定门（试点转正条件）

> 人工介入率 **< 30%** 且 返工率 **< 10%**（以提问者判定"是否被解决"为 ground truth）——达标方可进入下一场景。

**前置阻断项**：消息时间数据完整性必须先修（见 3.2），否则上述指标全部不可信。

## 6. 边界与不承诺清单

| 项 | 明确边界 |
|---|---|
| **排期估时** | **不承诺**。Agent 只提供范围、依赖、风险清单与历史耗时分布，不提供人天数字，不承担签字权 |
| **不可逆操作** | 合并、发布、对外沟通**一律人工确认**，不外包 |
| **权限模型** | **消息只能请求，不能扩权**。唤醒后的能力白名单写死在宿主侧，由消息内容决定权限的设计**不可接受** |
| **异见与溯源** | 异见位与结论溯源链是**必选项而非增强项**：若人未参与推演过程又拿不到溯源，对结论只能盲信 |
| **模型多样性** | L2 以上场景必须保留至少一个**非同族模型位**，否则同源盲区会静默回归 |
| **署名** | 替身发言必须标注身份，**不冒名** |

## 7. 风险登记

| # | 风险 | 表现 | 缓解 |
|---|---|---|---|
| **R1** | **相关性盲区** | 同厂同代模型在同一处一起错；而共识形成会**消除"分歧"这个唯一的告警信号**——方案听起来很完整，却无人能发现它错在哪 | 强制异见位 + 外部证据源 + 跨厂模型位 |
| **R2** | **决策带宽积压** | Agent 24h 出方案 → 人变 24h 审核瓶颈；"机器越干越多，人越审越累" | L2 并发上限约束 + 人类介入点前置声明 |
| **R3** | **静默失败** | 无人监督的长跑在漂移或死掉，而表现是"以为在推进，其实早停了" | 预算上限 + checkpoint + 可回滚 + **失败告警与重试**（实测发现当前调度器的网络类失败不会自动恢复） |
| **R4** | **记忆幻觉复利** | 错误记忆被反复召回，且越自信；`acp_memories` 被标注为不可清理资产 | 质量字段 + 引用回显 + 一键否决；验证不了的记忆标记为"未验证"而非累积票数 |
| **R5** | **遥测不可信** | 指标建立在错误的时间数据或残缺的分母上，结论不会被发现是错的，只会被采信 | 时间数据修复前置 + 三态分母 + 分母含失败 |
