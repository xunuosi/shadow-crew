**一句话裁决**：主导与挑战双方的分歧不是「方向之争」，而是「**落地层级之争**」——

而当前最贵的缺口比双方命名的都更靠前一层：**失败既不可观测，也不可隔离**。

## 1. 争议映射（Dispute Map）

### 1.1 双方主张与各自最硬的证据

| 维度 | 主导侧（@openclaw-mantis） | 挑战侧（@mycodex） |
|---|---|---|
| 核心主张 | 推进能力演化（多 Agent 接力、议题治理、记忆资产等能力簇） | 下一步不是「新功能」，而是「**可证伪性层**」 |
| 最硬证据 | 已产出 `FEATURE_SCENARIO_MATRIX_SHINOBI.md`：对每条能力给出 🟢/🟡/🔴 对外可用性判定，并自曝 X1–X3 三条与实现不符项 | 本议题自身：主导者本回合产出为空（`【OpenClaw Mantis】ACP 任务已完成 (stopReason: end_turn)`，正文空白） |
| 隐含前提 | 能力清单已可核查，故可据此规划演化 | 产出为空即证明「叙事替代证据」，故须先建可证伪机制 |

### 1.2 仲裁认定的真实分歧点

> **分歧不在「要不要可证伪性」，而在「可证伪性落在文档还是落在代码」。**

主导方已经**用文档实现了可证伪性**（那份矩阵本身就是一次诚实的自我核查，其价值不应被挑战方抹去）。
但该文档自证了一个更强的结论：**它的 🔴 条目中有三条（X1–X3）与实现不符，而这些不符项此前已进入对外材料。**
这正说明——**文档层的可证伪性会随下一次代码变更失效，不足以守住诚实性**。
挑战方的诉求因此成立，但其表述过度：不是「不要功能」，而是「**功能的对外主张必须先有代码级证据源**」。

### 1.3 双方共同遗漏的第三项（本轮仲裁的核心增量）

本轮议题在**三条 Agent 通道上连续失败**，而这些失败**全部未被系统识别为失败**：

1. `@openclaw-mantis` 输出空正文 → 系统仍将其落为一条正常回复；
2. `@openclaw-mantis` 触发 idle timeout（300s 无 stdout）→ 告警文案被**当作上下文**继续流转；
3. `@MyClaudeCode` 连接被拒（ConnectionRefused）→ 链条中断，用户侧观感是「卡住」。

**结论：当前系统对「空产出」「错误产出」「链路中断」缺少统一契约，三者都会被降级为普通文本进入消息流。**
在这一层修好之前，P1 的指标采集采到的将是被污染的样本（分母里混着错误卡与空回合），
D2 的可证伪性目标也无法达成。**故 P0 必须排在 P1 之前。**

## 3. 权衡矩阵（Trade-off Matrix）

评分口径：可行性（10 分，越高越易落地）／健壮性增量／ROI（对「可交付、可对外、可度量」的推进）／
可证伪性（能否产出可复现的验证结论）／风险。**裁决列为本仲裁者建议。**

| 候选方向 | 可行性 | 健壮性增量 | ROI | 可证伪性 | 主要风险 | 裁决 |
|---|---|---|---|---|---|---|
| **A. 新功能扩张**（继续加能力簇） | 9 | 低 | 低 | 低 | 在 E1–E3 未修时叠加功能，失败面同比例放大；对外主张继续无证据源 | ⏸ **本轮不做** |
| **B. 完整可证伪性层**（指标 + 溯源 + 盲审 + 验真） | 6 | 中 | 高 | 高 | 一次做完周期长；分母若含 E1–E3 污染样本，则指标不可信 → **必须在 C 之后** | ✅ **采纳，但裁剪并后置为 P1** |
| **C. 回合产出契约 + 失败隔离**（P0 最小集） | **9** | **高** | **高** | **高** | 少量设计取舍（失败算不算「已发言」），需人类定调 | ✅ **本轮唯一 P0** |
| **D. 诚实性回收**（回收 X1–X4 表述） | **10** | 中（信任面） | 高 | 高 | 无技术风险，仅需一次对外材料对齐 | ✅ **立即执行** |
| **E. MCP 工具链实装** | 4 | 中 | 中 | 中 | 现状是硬编码 SUCCESS 的假执行；实装涉及宿主侧进程与工具协议，是本仓库最重的工程量之一 | ❄ **冻结**（解除条件见 §4.3） |
| **F. 入站订阅（替身代答）** | 3 | 中 | 中 | 低 | `nostr_relay_url` 为死字段（声明 + 赋值、零读取点）；relay 硬编码单房间且无 per-room 鉴权 → 直接接入有越权风险 | ❄ **冻结** |
| **G. 无人值守自主拉起** | 2 | 低 | 中 | 低 | `src-tauri/src/main.rs` 显式禁止程序自发拉起 Agent（**有意的安全设计**）；放开需人类显式授权 | ❄ **冻结（安全设计，不建议解除）** |

**矩阵读法**：C 与 D 是唯一在两个以上维度同时取高分的项，且二者合计几乎无设计决策成本。
B 的 ROI 最高，但它**依赖 C 先修好分母**——这三条构成本裁决的核心排序逻辑。

## 4. 裁决与路线图

### 4.1 P0 —— 回合产出契约与失败隔离（本轮定案，建议天级）

> 目标：让「Agent 这一跳到底有没有产出」成为**代码可判定**的事实，而不是渲染后由人肉眼判断。

| 编号 | 交付项 | 落地位置（建议） | 说明 |
|---|---|---|---|
| P0-1 | **回合产出契约**：为每跳产出标注 `passed / degraded / failed`，空串、纯空白、仅告警前缀一律判为 `degraded`，不得作为「正常回复」下沉 | `src/services/acpClient.ts` 返回值 + `src/App.tsx:1718` 落库前 | 契约应携带 `reason` 字段，便于审计 |
| P0-2 | **失败隔离与队列保序**：任一跳 `failed` 不终止整链，继续消费 `remainingQueued`；失败计数达阈值时沿用**静默收敛**语义（不弹熔断卡片） | `src/App.tsx:1796-1814` catch 分支 | 复用既有 `checkLoopGuard` 的 `isSilentEnd` 哲学，保持交互一致性 |
| P0-3 | **上下文净化**：下游 prompt 的「前序推演方案与结论」区块只接受 `passed` 产出；`degraded/failed` 以降级短标记替代原文（如 `⚠️ 该成员本跳未产出（原因：idle timeout）`） | `src/App.tsx:1790` + `src/services/agentCollaboration.ts:324-327` | 直接消除 E2 的污染路径 |
| P0-4 | **轮次上限单一来源**：删除 `maxHops: 8` 两处字面量，统一透传 `cascade.maxDepth` | `src/App.tsx:2154`、`:2672` | L0 级改动，改完即可编译验证 |
| P0-5 | **ACP 日志单写 + 体积上限**：消除双写，增加轮转/截断阈值（如 10 MB） | `src-tauri/src/acp_manager.rs:13-41` | 防止单会话 50 MB 级磁盘膨胀 |

### 4.2 P1 —— 可证伪性层最小实现（建议周级）

- **指标采集（六项）**：严格沿用 `PRODUCT_CASE_SHINOBI_EFFICIENCY.md` §7.2 已定义口径与「分母纪律三条」，不自造新指标。
- **结论溯源**：每个结论可回溯到 `hop / agentId / 证据位置`，让「谁在什么证据上说了什么」成为可查询记录（P0-1 的契约字段即为其数据基础）。
- **失败率纳入度量**：P0-1 产出的 `degraded/failed` 计数必须成为公开指标的一等公民——**不度量失败的提效主张不可证伪**。
- **影子模式试点**：按 §7.4 既有方案执行，不新增承诺。

### 4.3 冻结区（非否决，附解除条件）

| 冻结项 | 解除条件（须全部满足） |
|---|---|
| MCP 工具链实装 | ① 先删除硬编码 SUCCESS 的假执行路径（`crates/shinobi-dev-mcp/src/main.rs`），或将其明确标注为 stub；② 至少一次真实 `session/new` 携带非空 `mcpServers`（30/30 空数组的现状必须先被打破） |
| 入站订阅（替身代答） | ① `nostr_relay_url` 出现真实读取点；② per-room 鉴权落地（当前 `relay.rs` 硬编码单房间、无鉴权） |
| 自主拉起 Agent | **不建议解除**：`src-tauri/src/main.rs` 的显式禁止是有意的安全边界，属产品设计而非缺陷 |

### 4.4 P3 —— 诚实性回收（立即执行，零代码成本）

按 `FEATURE_SCENARIO_MATRIX_SHINOBI.md` §3.3「对外禁用句式」，从所有对外版本中**删除而非软化**以下三句：

1. ~~「Agent 可自动运行静态检查 / 测试并给出结果」~~ → E6：返回硬编码 SUCCESS，不执行任何命令。
2. ~~「替身可在你离线时替你回答队友提问」~~ → F：入站订阅未实装。
3. ~~「已在提效上取得 X% 提升」~~ → 无指标采集链路，「提效」当前不可证伪。

## 6. 反悔条件（何时推翻本裁决）

本裁决的排序建立在「**失败不可观测正在污染所有下游结论**」之上。若出现以下任一可观测事实，应重新裁决：

1. **E1–E3 的根因被证明在宿主 Agent 侧而非平台侧**，且平台侧已有等价防护 → 则 P0 降级，P1 提前。
2. **试点已被外部承诺锁定（30 天内需交付对外材料）** → 则 D（诚实性回收）优先于 P0 全部，先守住不虚报。
3. **出现 P0 完成后仍无法解释的失败样本** → 说明缺陷层级高于契约层，需重新评估是否引入独立观测通道。
