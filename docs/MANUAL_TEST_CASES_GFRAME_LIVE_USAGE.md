## 1. 观测词典：执行时到底看哪里

| 观测位置 | 长什么样 | 用来判断什么 |
| :--- | :--- | :--- |
| **议题抽屉顶部五步流** | `① 提案立论 → ② 反例压测 → ③ 接地验证 → ④ 答辩修正 → ⑤ 仲裁定案` | 当前走到哪个阶段；第 ② 步显示 **「⚡ 压测旁路」** 表示该模块走了贝叶斯快速通道 |
| **🧩 G-Frame 模块沙箱矩阵** | 一行胶囊：`[mod-1] 标题 (0.20→0.16) ⚡` + 右上角「信息熵压降 xx% · x/y 已冻结」 | 模块拆分是否生效、每个模块的先验/后验风险、路由通道（⚡快速 / ⚔️深度）、冻结进度 |
| **系统提示卡（时间线内）** | `⚡ 贝叶斯快速通道`、`🧊 快速通道实证直通硬冻结`、`⚔️ 贝叶斯后验动态升级`、`🧊 模块收敛硬冻结 & 拓扑切换`、`🔄 触发模块沙箱局部重修`、`🛡️ 白名单正交归属收敛`、`⚠️ 快速通道降级告警` | 状态机的每一次自动决策都会留痕，这是最直接的验收证据 |
| **Wald-SPRT 序贯调控条** | 「轮次 N · 对齐分 xx% · 似然比 Λ=…」+ 状态标签 | 序贯收敛证据是否存在（全快速通道议题此前缺失，已修复） |
| **谄媚度治理 (BSS/DSS) 条** | BSS / DSS / γ 数值 | 红队与答辩阶段的谄媚抑制是否生效 |
| **💬 辩论记录 / 活体 ADR 画布**（右上切换） | ADR Markdown：公共契约 + 模块表 + 权衡矩阵 | 终局归档质量与模块级分治是否完整沉淀 |
| **人类首席仲裁官法槌控制台**（抽屉底部） | `采纳提案` / `采纳红队` / `权衡矩阵` 三个按钮 + 豁免勾选区 | 人类终审是否可正常行使；是否被误判为「法定人数未达标」 |

**数据级取证（可选，排查用）**：浏览器 DevTools → Application → Local Storage → 键 `shinobi_messages`，找到你的议题对象后查看 `topicData.gameTheoreticState.modularState`，可看到完整的 `modules[]`、`belief.priorRisk/posteriorRisk`、`routingMode`、`whitelistDeduplications`。遥测事件在 `shinobi_cogno_telemetry_events_v1`。

## 3. LIVE-01 研发类·混合风险议题（主链路，优先跑这条）

### 前置条件
1. 已创建频道（若首页提示「暂无活跃频道」，点击 **「创建第一个频道」** → 弹窗「创建协同频道 (Channel)」→ 填写频道名称/描述 → 勾选初始邀请的 Agent → **「立即创建频道」**）。
2. 3 个 Agent 均已 Start 在线。

### 输入（直接复制粘贴）

**议题标题**

```
渠道级数据隔离与订单同步引擎改造
```

**议题描述**

```
为多租户场景引入渠道级数据隔离，需要三块协同改造：

## 一、共享类型契约与租户不变量
定义 OrderContext 类型契约、租户标识常量与跨模块不变量，纯类型与常量，无运行时副作用。

## 二、订单同步引擎的并发调度与事务改造
重写同步引擎的并发调度、分布式互斥锁、幂等提交与迁移回滚，属于高风险核心链路，需处理超时与重试。

## 三、渠道面板同步状态与冲突提示
在渠道面板展示同步状态、冲突提示与重试入口，纯前端展示映射。

约束：引擎层禁止直接操作底层 SQLite，必须经由 Repository 接口。
```

### 操作步骤
1. 在频道时间线右上角点击 **「新建议题」** → 弹出「发起新议题 (New Topic)」。
2. 粘贴上面的**标题**与**描述**。
3. 在 **「讨论模式选择」** 中选择 **「4+1博弈决策模式」**（副标题：`♟️ 4+1 认知协同攻防决策 (提案/红队/接地/综合 + 人类法槌)`）。
4. 在 **「指派协同推演 Agent」** 中勾选 3 个 Agent，并分别为它们指派角色：
   - A → **提案**
   - B → **红队**
   - C → **接地**
   - 人类首席仲裁官（你本人）保持持槌。
5. 点击弹窗底部的主按钮发起议题，抽屉应自动打开「议题」视图。

### 预期结果（逐项勾选）

**阶段 0~1 模块拆解**
- [ ] 抽屉顶部出现 **「🧩 G-Frame 模块沙箱矩阵」**，模块数为 **2~4 个**（不是 1 个，也不是 5 个以上）。
- [ ] 每个模块胶囊都显示了 `[模块ID] 标题 (先验→后验)` 与一个通道图标：`⚡`（快速验证流）或 `⚔️`（深度红队对抗流）。
- [ ] 右上角显示 **「📜 公共契约已锁定」**；点开 ADR 画布能看到《跨模块公共接口契约》章节。
- [ ] 每个模块都各自有一条 **模块级提案**（时间线上该模块沙箱内有提案发言），而不是只有第一个模块提案、后续模块直接压测。

**阶段 2~4 双轨路由**
- [ ] 被判定为 **⚡ 快速验证流** 的模块：出现系统提示卡 **「⚡ 贝叶斯快速通道 (fast_track)」**，并且**没有**该模块的红队质询卡。
- [ ] 被判定为 **⚔️ 深度红队对抗流** 的模块：出现 **「⚔️ 反例压测」** 环节（红队发言必须包含失效场景与检验要求），随后进入接地验证与答辩。
- [ ] 至少一个模块走完 `提案 → 红队 → 验证 → 答辩`，至少一个模块走 `提案 → 验证`（若你的 Agent 把三个模块都标注为高风险，则全部走深度通道，此项可标 N/A）。

**多模块闭环（本轮最关键）**
- [ ] 抽屉矩阵的 **「x/y 已冻结」** 会随讨论推进增长，最终达到 **N/N**。
- [ ] 每次冻结/切换都会出现系统卡：**「🧊 模块收敛硬冻结 & 拓扑切换」** 或 **「🧊 快速通道实证直通硬冻结」**，文案里会点名下一个要激活的模块。
- [ ] **只有 N/N 全部冻结后**，议题才进入「⑤ 仲裁定案」；中途不会带着未冻结模块跳进仲裁。
- [ ] 若某模块被判越界/证伪，会出现 **「🔄 触发模块沙箱局部重修 (SCOPED_DEFENSE_REFINE)」**，且已冻结模块的状态与结论**不回退**（对比重修前后的矩阵：已完成模块仍显示 🔒）。

**仲裁与归档**
- [ ] 抽屉底部「人类首席仲裁官法槌控制台 (Chief Arbiter's Gavel)」出现 **采纳提案 / 采纳红队 / 权衡矩阵** 三个按钮，且**未被**「法定推演人数未达标告警」拦住（前提是红队确实参与了）。
- [ ] 点击 **「权衡矩阵」** 或 **「采纳提案」** 完成定案，抽屉顶部状态变为「已定案」，时间线出现《仲裁定案裁决书》。
- [ ] 切换到 **「活体 ADR 画布」**：文档包含 ①业务背景与架构假定 ②跨模块公共接口契约与原子模块分治（模块表含 `P_prior → P_posterior`、路由通道、状态、允许文件白名单）③架构权衡矩阵与终局决议 ④落地影响文件清单。
- [ ] 点击 ADR 画布的**复制**或**下载**按钮，能得到完整 Markdown。
- [ ] （可选）点击 **「指派落地 Agent」** 让某个 Agent 实际改代码，完成后出现执行报告。

### 判定通过标准
上述「多模块闭环」四项全部勾选 + 仲裁可正常敲锤 + ADR 含模块表 → **LIVE-01 通过**。

### 失败取证
截图：模块矩阵、缺失/异常的系统提示卡、法槌控制台；并导出 ADR Markdown 一并附上。

## 4. LIVE-02 全低风险议题（验证贝叶斯快速通道）

### 目标
验证 `fast_track` 真的跳过红队、不误报「压测缺席」、且仍有收敛证据（对应近期修复的 N8 / N11 / N13）。

### 输入（直接复制粘贴）

**议题标题**

```
研发文档结构与术语一致性整理
```

**议题描述**

```
本议题为纯文档整理工作，不涉及并发、事务、鉴权、数据迁移或资金相关逻辑。

## 一、文档结构整理
统一 README 与 docs/ 目录的章节标题与编号，纯文本编辑。

## 二、术语表与文案校订
补充术语表并统一中英文用词，属纯内容校对。

## 三、历史内链与外部链接核对
逐条核对文档内链与外部链接可达性并记录结论，属低风险核对工作。

拆解要求：请在模块拆解时把全部模块的 complexity_level 标注为 low_deterministic（本议题无高风险模块）。
```

### 操作步骤
同 LIVE-01（4+1 模式，指派 提案 / 红队 / 接地 三角色；红队仍然指派但预期不会被调用）。

### 预期结果
- [ ] 模块矩阵中**所有**模块都标 `⚡`；右上角没有 `⚔️` 模块。
- [ ] 每个模块在提案后立即出现 **「⚡ 贝叶斯快速通道 (fast_track)」** 系统卡，随后进入「③ 接地验证」。
- [ ] 时间线中**没有**红队质询卡（红队 Agent 全程未被调用）。
- [ ] 验证通过后出现 **「🧊 快速通道实证直通硬冻结」**，文案指明「全部模块已完成实证收敛，正在转入终局仲裁」。
- [ ] 抽屉第 ② 步「反例压测」显示为 **「⚡ 压测旁路」**（emerald 绿色语义），**不是** 琥珀色「⚔️ 压测缺席」。
- [ ] 法槌控制台**不出现**「法定推演人数未达标告警 (Quorum Not Met)」，**不需要**勾选「我已知晓红队缺席风险，并执行人类首席仲裁官具名特权豁免」即可直接定案。
- [ ] ADR 或状态条中能查到序贯收敛证据（SPRT 调控条出现，或 ADR 含收敛记录），而不是完全空白。

### 失败判据
只要出现以下任一情况即为**未通过**：
1. 弹出「法定推演人数未达标 / 红队缺席豁免」而实际红队是被设计性旁路；
2. 红队仍被调用（快速通道未生效）；
3. 快速通道议题全程没有任何收敛证据。

### 备注
如果落到了「系统自动兜底拆解」路径（你的 Agent 未调用 `submit_module_decomposition` 工具），模块复杂度会按标题自动推断，通常只有第一个模块是低风险 —— 此时本用例会退化为「混合通道」，属**环境限制而非缺陷**，请记录 Agent 名称与是否支持 MCP 工具调用。

2026 Q4 SaaS 会员分级定价与存量老客迁移方案

围绕客单价提升与续费留存率平衡展开业务推演。

## 一、阶梯定价与毛利测算模型
明确基础版与企业版权益差异与毛利测算口径。

## 6. LIVE-04 未指派验证官（验证快速通道降级）

### 操作
沿用 LIVE-01 的输入与操作，但在「指派协同推演 Agent」时**只指派 提案 + 红队**，**不指派 接地验证官**。

### 预期结果
- [ ] 低风险模块在被判定为快速通道时，出现 **「⚠️ 快速通道降级告警 (Fast-Track Downgraded)」** 系统卡，文案说明「当前议题未指派接地验证官 (Verifier)…自动降级为标准深度博弈 (deep_debate)」。
- [ ] 该模块随即进入 **「⚔️ 反例压测」** 而不是卡在验证阶段。
- [ ] 议题可以继续推进到仲裁，不会出现「接地验证者缺席」后卡死不动的情况。

## 7. LIVE-05 红队缺席（验证法定人数门禁）

### 操作
沿用 LIVE-01 的输入，但只指派 **提案 + 接地验证**，**不指派红队挑战者**。

### 预期结果
- [ ] 出现系统卡 **「⚔️ 法定推演人数告警 (Quorum Alert)」**，说明未指派/未匹配到制衡方。
- [ ] 抽屉底部出现琥珀色 **「法定推演人数未达标告警 (Quorum Not Met)」**，普通快速敲锤被拦截。
- [ ] 勾选 **「我已知晓红队缺席风险，并执行人类首席仲裁官具名特权豁免 (Exemption)」** 并填写理由后，方可完成定案。
- [ ] 定案后，裁决书/落库记录中出现该豁免理由（审计留痕）。

> 这条与 LIVE-02 是一对：**真缺席（LIVE-05）必须被拦；设计性旁路（LIVE-02）必须被放行**。两条都符合才算门禁语义正确。

## 8. LIVE-06 模块矩阵过滤与 ADR 归档

可在 LIVE-01/LIVE-02 进行中或结束后执行。

### 操作与预期
- [ ] 点击矩阵中任一模块胶囊 → 时间线**只显示该模块沙箱内的发言 + 全局契约类记录**，顶部出现「🧩 当前已开启物理沙箱隔离视图：仅展示模块 [mod-x] 及全局契约记录」横幅。
- [ ] 再次点击该胶囊（或点击「显示全部」）→ 回到「全部模块 (N)」视图。

## 11. 常见问题排查

| 现象 | 可能原因 | 处置 |
| :--- | :--- | :--- |
| 议题发起后长时间无响应 | 对应角色 Agent 未 Start / 离线 | 检查左侧该 Agent 卡片是否绿色呼吸灯；重新点击 Start |
| 抽屉顶部没有「🧩 G-Frame 模块沙箱矩阵」 | 讨论模式未选「4+1博弈决策模式」；或议题创建时未初始化 modularState | 编辑议题确认模式；或重新发起议题 |
| 模块数为 3 但只有一个模块被推进 | 旧版本行为（多模块闭环缺陷） | 当前基线应已修复；若复现请抓取系统提示卡与矩阵截图回报 |
| 一直是「⚔️ 压测缺席」而不是「⚡ 压测旁路」 | 快速通道旁路语义未生效 | 记录是否全模块 `⚡`；附抽屉第 ② 步截图 |
| 快速通道议题仍被要求签署红队缺席豁免 | 门禁误判 | 同上，附豁免横幅截图 |
| ADR 里缺少模块表或公共契约 | ADR 拼装未读到 modularState | 检查 LocalStorage 中 `modularState.enabled` 是否为 true |
| 想重新开始 | —— | 「存储架构与缓存管理 (SQLite & 日志)」→ 清理本地缓存，然后重建频道/议题 |
