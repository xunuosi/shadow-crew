## 0. 一页纸决策结论

**用户问题**：「后续 Shinobi 最应该开发哪方面的功能？」

**决策答案（一句话）**：

> **下一阶段最该做的不是"新功能面"，而是"把已写进产品定义、但尚未接通的那条链路接上"——即宿主侧入站订阅（离线替身答疑）。**

**理由（可证伪）**：Shinobi 对外叙事的第一价值场景是「人不在场时，替身代表你回答队友提问」。
但实测该链路**当前不成立**（§2 证据 E1/E2/E3）。此时若继续扩张功能面（新增面板、新增角色、新增指标），
只是在一台**尚未接入外部世界的工作台**上继续加装饰，边际价值趋近于零。

**四项决策（按优先级）**

| # | 决策 | 类型 | 为什么是它 |
|---|---|---|---|
| **D1** | **主机侧入站订阅**（首期按"排队不唤醒"落地） | 🟢 必做 | 唯一能把"离线替身"从叙事变成产品的改动；不触碰 `main.rs:100` 安全设计 |
| **D2** | **博弈模式补上「盲审期 + 举证接地」** | 🟢 必做 | 博弈 UI 已在工作树落地，但缺盲审与验真 → 治理仍是"自由讨论"的装饰 |
| **D3** | **可信度底座**：结构化事件落库 + 记忆质量字段 + 只读健康度面板 | 🟢 必做 | 无此三项，任何"提效 X%"的对外主张都不可证伪，评审一击即穿 |
| **D4** | **MCP 工具链：先摘谎，后实装** | 🟡 止损 | 现状 `tools/call` 返回硬编码 SUCCESS；先改为显式 unsupported，再评估真实装 |

**一项明确不做（Non-Goal）**：把"技术排期"作为可外包场景。排期是历史数据拟合 + 承诺兑现，非推理题，且试点周期内无 ground truth 可闭环。

## 1. 决策背景：为什么"该开发哪方面"这个问题必须先重建基线

本轮推演的前 7 轮出现三类无效消耗，本身就是决策依据的一部分：

- 主导者首轮**空输出**（只回 `end_turn`）；
- 第二/三轮**双端 ACP 通信告警**（Connection refused / idle timeout 300s）；
- 讨论在"Shinobi 是什么"这一层反复重建，缺乏**共享的、可复现的事实基线**。

因此本决策文档不以"愿景排序"立论，而以**实测基线**立论：先钉死"哪些能力真存在、哪些只是文档里的句子"，
再决定往哪里投研发资源。下文所有数字均可一条命令复现（§7）。

## 3. 候选路线对比与选型

| 路线 | 内容 | 收益上界 | 当前可行性 | 判定 |
|---|---|---|---|---|
| **A. 链路接线优先** | 入站订阅 + relay 鉴权 + 结构化事件 | 打开"离线替身"这一**唯一不依赖流程改造**的场景 | 改动面小、不触碰安全红线、可 L1 验证 | ✅ **选定为主线** |
| **B. 治理深化优先** | 盲审期 + 举证接地 + 异见位 | 提升"方案讨论"结论可信度 | 依赖 A 的落地经验与事件底座 | ✅ **选定为并行支线**（与 A 无资源冲突） |
| **C. 功能面扩张优先** | 新增面板/角色/指标/集成 | 演示效果佳 | 在未接通的底座上加装饰，**边际价值≈0** | ❌ **否决** |
| **D. MCP 工具链实装优先** | 打通自动静态检查 / 测试执行 | 让"变更预审"成立 | 需先解决安全沙盒与工具鉴权，成本 > A + B | ⚠️ **延后**（先摘谎，见 D4） |

**选型逻辑**：可替代度 ≈ 1 / 人工验证成本。A 与 B 产出落在 **L0/L1**（可机器验证或可引用证据），
C 与 D 的产出落在 **L2/L3**（需人持续在上下文里复核），在当前资源下应当后置。

## 4. 落地路线图与验收标准

### P0（本阶段必做 · 三项）

| 项 | 内容 | 验收标准（可判定） | 难级 |
|---|---|---|---|
| **P0-1** | relay **per-room 路由 + 订阅鉴权**，替换 `relay.rs:46` 硬编码房间 | `relay.rs` 中不再出现字面量 `"room-acp-dev"`；未授权订阅返回明确拒绝码；单测覆盖越权订阅 | L1 |
| **P0-2** | 宿主侧**入站订阅**，首期**「排队不唤醒」**形态（消息落库 + UI 提示，不自动拉起 Agent） | `nostr_relay_url` 出现**读取点**；收到房间消息后 `messages` 表新增 1 行且 `main.rs:100` 行为不变（无自动 Start） | L1 |
| **P0-3** | **结构化事件落库**：`log_acp_event` 双写 SQLite 结构化表（按 `topic_id` / `agent_id` / `event_type` 索引），文本日志降级为调试开关 | 可按议题聚合查询；`acp.log` 停止重复落盘同一大对象；表结构含索引 | L1 |

### P1（紧随其后 · 与 P0 并行无冲突）

| 项 | 内容 | 验收标准 | 难级 |
|---|---|---|---|
| **P1-1** | **盲审期（Delphi Blind Phase）**：首轮各 Agent 独立起草、互不可见，全员提交后揭盲 | 首轮 `session/prompt` 中不含其他 Agent 输出（可抓报文验证）；揭盲事件落库 | L1 |
| **P1-2** | **举证接地**：事实性断言强制附证据（命令/行号/日志），无证据断言在裁决权重上降档 | 挑战者发言可被系统校验出"无凭证"标记；权重规则可配置 | L1 |
| **P1-3** | `acp_memories` 增 **质量字段** + 引用回显 + 一键「不准」 | 表增 `verified_by`/`feedback`/`last_used_at`；UI 可对单条记忆标记失效 | L1 |
| **P1-4** | **只读健康度面板**（聚合视图，纯读） | 原料取自 `messages`，零新增采集链路 | L0 |

### P2（下一阶段评估）

| 项 | 内容 | 前置条件 |
|---|---|---|
| **P2-1** | 脱敏 / 打包**下沉 Rust 侧**，只读改为**进程级**强制 | 现仅前端自律 |
| **P2-2** | **异见位 + 跨厂模型位**写入机制 | 打破同源相关性盲区 |
| **P2-3** | MCP 工具链**真实装**（含安全沙盒与工具鉴权） | 先完成 D4 摘谎；沙盒方案需 L2 评审 |
| **P2-4** | 「离线替身答疑」从"排队"升级为"可唤醒" | 需仲裁者**显式授权**修改 `main.rs:100` |

## 5. 风险登记与应对

| # | 风险 | 触发条件 | 应对 |
|---|---|---|---|
| R1 | **开放唤醒通道引入越权** | 入站订阅上线但鉴权缺失 | P0-1 **必须**先于 P0-2 合入；未鉴权的唤醒通道不得开放 |
| R2 | **记忆错误复利放大** | 错误记忆写入即终态，随召唤重复生效 | P1-3 质量字段 + 一键失效必须与"记忆资产"叙事同步对外 |
| R3 | **虚假能力主张被侦察击穿** | 对外材料出现"自动跑静态检查/测试" | D4 摘谎：`tools/call` 改为显式 `unsupported`，同时回收文档中 X1–X3 说法 |
| R4 | **多 Agent 讨论退化为共识幻觉** | 同源模型 + 无盲审 + 无验真 | P1-1/P1-2 与"异见位"绑定落地；结论必须可溯源 |
| R5 | **事件日志继续膨胀** | 文本 append 无限增长（已 26.6 MB） | P0-3 双写结构化表 + 文本日志轮转/降级 |
| R6 | **时间戳不可信导致指标失真** | `timestamp` 与 `id` 内嵌 epoch 不一致 | P0-3 落地时以**单一权威时间源**重写；修复前禁用"决策延迟"类指标 |

## 6. 明确不做（Non-Goals）

1. **不做**技术排期承诺外包（L3，不可回滚）→ 降级为范围/依赖/风险清单 + 历史耗时分布供给。
2. **不做**为演示追加装饰性面板与模拟指标（`RustTauriArchitectureHub` 式硬编码数据不再新增）。
3. **不做**在无鉴权前提下开放任何唤醒/入站通道。
4. **不做**"提效 X%"类无采集链路支撑的量化声明。
