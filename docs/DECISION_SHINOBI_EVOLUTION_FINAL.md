## 0. 一页纸决策（Executive Decision）

**用户问题**：「后续 Shinobi 最应该开发哪方面的功能？」／后续追问：「我没有看到任何博弈效果」

## 4. P0 技术方案（修订后 · 关键路径）

### P0-a：回合产出契约（D1）

```ts
type AcpOutcome =
  | { status: 'ok';        text: string; durationMs: number }
  | { status: 'empty';     reason: 'end_turn_no_content'; durationMs: number }
  | { status: 'error';     kind: 'timeout'|'refused'|'offline'|'network'|'protocol'; message: string; durationMs: number }
  | { status: 'truncated'; reason: 'max_duration'; durationMs: number };
```

- **P-1 落库守卫**：仅 `ok` 且非空白写 **Agent 消息**；其余写**系统事件**（非 Agent 作者、独立徽标），**永不进入级联 prompt**。
- **P-2 消费守卫**：`buildCascadePrompt` 仅消费 `ok`。
- **P-3 失败隔离**：失败跳标 `skipped`，**继续消费 `remainingQueued`**；队列空则以显式终止原因收尾。
- **P-4 单常量收口**：`maxDepth`/`maxHops` 统一为单常量来源（含落库），并带 `schema_version`（见 §6-R2）。

### P0-b：博弈编排门禁（D2）

| 序 | 机制 | 关键设计（含 R2/R3/R4 修正） |
|---|---|---|
| **G0** | 博弈态首轮改**串行两阶段** | 阶段一：主导者独立落盘 → 生成**结构化标的**（方案 id+版本+claims）。阶段二：标的作为"待攻击对象"下发挑战者 |
| **G1** | `evaluateGameQuorum`：制衡方缺席**默认禁裁** | 无有效挑战 → 议题不得进入 `resolved`，UI 显式提示「⚔️ 制衡方未回应，不予裁决」；**仲裁者可具名豁免**（落库 + UI 标注） |
| **G2** | 博弈态角色指令拼接在 `standingContext` **之后**；挑战者义务替换 | 挑战者首发言须为「有效挑战」或「具名声明无可挑战」，二者皆无 → 走 G1 豁免路径 |
| **G3** | `gameRoles` 三角色过滤 + **派发前二次校验** | 缺任一角色阻断提交；派发前再校验 `gameRoles ⊆ participatingAgentIds` |
| **G4** | 占位符/告警标 `isFailure`，排除出 `recentHistory`，UI 呈现「席位空缺」 | 依赖 P0-a 契约（R6） |

### P0 验收判据（可执行故障注入）

| # | 注入方式 | 通过标准 |
|---|---|---|
| **A** | 某跳返回空正文 | `messages` 表**不新增 Agent 行**；新增 1 行系统事件 |
| **B** | 某跳触发 idle timeout | 下一跳 prompt 的「前序推演方案与结论」中 `⚠️` 与 `任务已完成` **零命中** |
| **C** | 第 2 跳抛错（第 3 跳已排队） | 第 3 跳**仍被派发**；议题终态含终止原因 |
| **D** | 跑满一轮查库 | 落库 `maxHops` **== 12**；且带 `schema_version` |
| **E** | 跑一轮后比对 | `logs/` 与 `src-tauri/logs/` **仅一份增长** |
| **F** | 挑战者超时（复现本议题） | 裁决入口**禁用**并给出原因；**仲裁者豁免后可裁决**且豁免记录落库 |
| **G** | 挑战者回复一段无引用的泛化风险清单 | 判为**无效挑战**，不解除禁裁 |
| **H** | 挑战者回复引用主导方案 `claim_id` + 失效场景 | 判为**有效挑战**，允许进入裁决 |
| **I** | 角色指向非议题成员 | 提交**与派发**两处均被拦截 |
