# 2026-11-10 补丁可信落地、真实验证与一键回退闭环改造日志

## 1. 改造背景

在代码开发与 Bug 修复场景中，议题落地链路存在三个会破坏可信度的问题：

1. **伪成功**：Rust `apply_workspace_patch` 用大量 `let _ =` 吞掉写入失败，最后无条件返回 `ok: true`；前端在 Tauri IPC 失败时还会伪造 `workspace_memory` 模式并返回成功。
2. **无验证**：补丁写入后没有任何宿主侧验证命令，Agent 只能“自称完成”，语法错误、构建失败、文件冲突无法进入下一轮修复。
3. **无回退与并发保护**：补丁直接覆盖目标文件，没有快照；两个并行议题同时修改同一文件时可能静默互相覆盖。

本次改造围绕 **“补丁是否真实落盘 → 是否有真实验证证据 → 失败能否收敛或回退”** 形成闭环。

## 2. 功能点与实现

### 2.1 P0-1 补丁应用结果去伪存真

`src-tauri/src/main.rs`：

- `AppliedFileStatus` 新增 `status`（`applied / conflict / archived_only / failed`）、`backup_path`、`error`；
- `ApplyWorkspacePatchResult` 新增 `applied_count`、`failed_count`、`history_id`、`history_path`；
- `ok` 仅在**每个补丁都真实应用成功**时为 `true`；
- 归档 `.patch`、重构源码、目录创建失败都会降级为 `failed`，不再静默吞错；
- 目标文件已存在时先执行 `git apply --check` 预检，再执行 `git apply`；预检失败才尝试块替换；
- `git apply` 与块替换都失败时返回 `conflict`，**禁止覆盖基线不一致的现有文件**；
- 创建新文件时若目标已被其他补丁创建，返回 `conflict` 而不是覆盖。

前端 `src/services/acpClient.ts`：

- 删除 `workspace_memory` 虚拟成功回退；
- 浏览器预览环境 / Tauri IPC 异常统一返回 `ok: false` 和逐文件失败原因；
- 新增 `rollbackTopicPatchFromWorkspace` 调用宿主回退命令。

`src/App.tsx`：

- 不再把所有 diff 无条件标记为 `applied`；
- 按宿主返回的真实 `status` 写入 `applyStatus / applyError / targetPath / backupPath`；
- 只有至少一个文件真实落盘时才把议题置为 `applied`，否则置为 `failed`；
- 已真实落盘的 diff 在再次合入时自动跳过，避免重复应用制造冲突。

### 2.2 P0-1 历史快照与一键回退

- 每次合入在归档目录写入 `.patch-history/<historyId>/manifest.json`；
- 修改已有文件前，先把原文件快照写入 `.patch-history/<historyId>/backups/<relativePath>`；
- manifest 记录每个文件的 `existed_before / before_hash / after_hash / mode / status`；
- 新增 Tauri 命令 `rollback_workspace_patch`：
  - 校验 manifest 必须位于当前 Workspace Binding 的归档目录内；
  - 目标路径必须仍位于工作区根目录内；
  - 仅回退 `status === applied` 的文件；
  - 回退前比较当前文件指纹与合入后的 `after_hash`，用户已再次修改时返回 `skipped_modified`，**绝不覆盖用户新改动**；
  - 新建文件仅在指纹一致时删除。

### 2.3 P0-3 补丁串行化与基线冲突检测

- `AppState` 新增 `patch_locks`：按目标文件绝对路径分配进程内互斥锁，同一文件串行落盘；
- `AppState` 新增 `workspace_operation_locks`：同一工作区的「合入 / 回退 / 验证」严格串行，避免验证读到半写入状态；
- 预检 + 块替换精确匹配 + 创建前二次检查共同构成基线校验；
- 基线不一致返回 `conflict`，不再静默覆盖。

### 2.4 P0-2 宿主真实验证门禁

Rust 新增 `run_workspace_command`：

- 仅允许白名单程序：`npm / npx / pnpm / yarn / node / cargo / tsc / git / go`；
- `cwd` 固定为 Workspace Binding 根目录；
- Windows 通过 `cmd /C` 调用 `.cmd` 垫片，并拒绝 `& | < > ^ % "` 等 shell 解释字符；
- 默认超时 120 秒（夹取 5~600 秒），超时自动终止；
- 返回真实 `exit_code / success / timed_out / duration_ms / stdout / stderr`；
- stdout / stderr 各保留尾部 16000 字符，避免 IPC 载荷膨胀。

前端新增 `src/services/workspaceVerification.ts`：

- 读取工作区 `package.json`，**只根据真实存在的 `scripts.lint` / `scripts.build` 生成验证计划**；
- 没有脚本或没有 Tauri IPC 时明确标记 `skipped`，不伪造 `passed`；
- 前序命令失败立即停止，避免无意义重复执行；
- 验证报告写入 `GameTheoreticState.executionVerification`，并在时间轴输出命令、退出码、耗时与输出尾部；
- 验证失败时提取结构化错误摘要，自动回派执行 Agent 修复，次数受该 Agent `maxCorrectionRetries` 限制；用尽后明确提示人工处理或回退。

### 2.5 UI 真实状态与回退入口

- `TopicMessageCard`：新增「验证中 / 验证通过 / 验证失败 / 验证未执行」状态胶囊，新增「回退本次合入」按钮；
- `ChatTimeline` / `TopicThreadDrawer` / `LivingAdrCanvas`：透传回退回调，并在已合入区域提供回退按钮；
- 验证运行期间禁用重复合入按钮。
