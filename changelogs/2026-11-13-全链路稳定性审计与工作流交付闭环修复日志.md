# 2026-11-13 全链路稳定性审计与工作流交付闭环修复日志

## 1. 背景

以「本地长期运行的程序员工作台」为视角对现有实现做了一次全链路审计，重点关注三类问题：

1. **功能闭环缺口**：工作流「应用补丁」点击无效、多文件 Diff 被截断、运行中无法取消、持久化态 `running` 自锁；
2. **资源与生命周期缺陷**：退出时全局锁饥饿导致子进程残留、子进程树未被完整终止、DB 互斥锁中毒、`acp.log` 无上限增长、前端事件监听与拖拽监听泄漏；
3. **响应效率**：简单问题仍按「全员扇出」广播，导致首个正确回答被多 Agent 并发拖慢。

本日志记录本轮全部修复、验证证据与仍未闭环的遗留项。

## 2. 后端（Rust）稳定性修复

### 2.1 `fix(acp-runtime)`：会话清理不再阻塞全局管理器锁

- `clear_sessions_with_generation` 改为 `prompt_lock.try_lock()` 非阻塞探测：只有真正持有 prompt 锁时才发送 `session/close`，避免在退出清理路径上等待长时间运行的 prompt 而拖垮 `stop_all`。
- 配合上一轮退出清理的超时包装（`tokio::time::timeout(12s, cleanup)`），窗口关闭不再因单 Agent 卡死而无期限挂起。

### 2.2 `fix(process-lifecycle)`：Windows 下按进程树终止 ACP 子进程

- `stop_agent` 在 Windows 上先执行 `taskkill /PID <pid> /T /F`，再走 `child.kill()`，确保 ACP 运行时派生的孙进程一并回收。
- `main.rs` 新增 `spawn_and_reap(cmd)`：所有 18 处「fire-and-forget」的系统调用（资源管理器、编辑器、清理脚本等）统一 `spawn` + 后台 `wait` 回收句柄，消除僵尸进程与句柄泄漏。

### 2.3 `fix(persistence)`：DB 互斥锁中毒不再导致整库不可用

- `db_manager.rs` 全部 32 处 `.lock().unwrap()` 改为 `.unwrap_or_else(|poisoned| poisoned.into_inner())`：任一写入线程 panic 后，后续读写仍可继续，而不是让整个持久化层永久 panic。

### 2.4 `fix(db-io)`：批量写入消息移出主线程

- `db_save_messages_batch` 由同步命令改为 `async fn` + `tauri::async_runtime::spawn_blocking`，大消息量落库不再阻塞 Tauri 主线程（UI 卡顿）。

### 2.5 `fix(acp-log)`：日志轮转与尾部读取

- `log_acp_event` 增加 20 MB 阈值轮转（`acp.log` → `acp.log.1`），杜绝长期运行后的无限增长。
- `read_recent_acp_logs` 改为「seek 到尾部 + 最多读取 1 MB + `from_utf8_lossy` + 丢弃首行残片」，不再整文件载入，也不会因任意 seek 落在 UTF-8 边界而失败。

## 3. 前端工作流交付闭环

### 3.1 `fix(topic-workflow)`：「应用补丁」真正生效

- `TopicThreadDrawer` 的 `onApplyTopicPatch` 签名扩展为 `(topicId, customDiffs?)`，并 `await` 调用结果；此前绑定的是无参数版本，点击后静默无操作。
- 落地执行同时写入 `diffView` 与 `diffViews`，多文件补丁不再只保留首个文件。

### 3.2 `feat(topic-workflow)`：运行中可取消

- `WorkflowProgressStrip` 新增 `onCancel`，运行态显示终止按钮；`App` 接到 `cancelTopicWorkflow(topicId, reason)` 并联动 `handleAbortAll`，取消原因写入进度条 `blockingReason`。

### 3.3 `fix(topic-workflow)`：持久化 `running` 自锁自愈

- 应用重启后若持久化状态停留在 `running` 而内存中无对应运行锁，自动迁移为 `cancelled` 并写入 `blockingReason` 与系统提示「♻️ … 已自动恢复为可重新运行」，避免议题永久卡死。

### 3.4 `fix(topic-workflow)`：排队语义与提示一致

- 运行中收到新输入时真正入队（`pendingRunRef`），并在当前阶段结束后通过 `queueMicrotask` 自动以该输入重跑；提示文案与实际行为对齐，不再「说排队但不排」。

### 3.5 `fix(game-fsm)`：提案阶段失败不再静默

- `useGameTheoreticFsm` 新增 `postStageFailure`：无可用提案方、提案为空或出错时，写入 `kind: 'error'` 的系统消息（「CognoNexus 阶段守护 ⛔」），用户能明确看到阶段为何停摆。

## 5. 响应效率：简单问题快答路由

新增 `src/services/intentRouter.ts`：

- `isSimpleQuestion(text)`：≤180 字符、无代码块、无显式 `@`、无复杂意图关键词（评审/重构/架构/分析/迁移/并发…），且为疑问句或疑问词开头（≤120 字符）。
- `pickFastPathAgent(agents)`：优先选择在线（`running`）Agent，否则回退首个。
- `resolveFastPathResponder(text, candidates)`：命中时把本轮并发扇出收窄为单 Agent，简单问题不再等待全员广播。

标准议题与频道两条路径均已接入。复杂诉求仍走原有多 Agent 编排，不受影响。

### 7.1 未覆盖与遗留项（如实记录）

1. **真实运行期验证缺失**：本轮未启动真实 Tauri 桌面端，未人工验证双主题 UI 状态矩阵、窗口关闭后进程树是否清空、远程 ACP 断线重连。
2. **macOS/Linux 进程树终止未实现**：仅 Windows 使用 `taskkill /T`，其它平台仍为单层 `child.kill()`（需引入 process group / `setsid`）。
3. **工作流后续追问**：目前仅实现「排队重跑」，未实现复用前序交接物的增量续跑。
4. **未实现能力**：消息级重试、跨议题/消息全局搜索、会话导出、Token/成本可视化、长会话虚拟滚动与分页。
5. **SPRT 早停/死锁熔断**：实现存在，但当前配置下部分分支在常规对话中不可达，参数标定仍需真实流量校验。
6. **模型选择器仍为展示态**：`modelName` 未随 ACP `session/new` 下发，实际模型由运行时自身配置决定。
