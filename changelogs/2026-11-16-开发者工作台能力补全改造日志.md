# 2026-11-16 开发者工作台能力补全改造日志

## 1. 背景

以「本地长期运行的开发者工作台」为目标，补齐此前审计中确认缺失的七项能力，按风险与依赖顺序分七批交付：

1. Token 与成本的可视化（ACP 真实用量透传）
2. 单条消息重试 / 跨议题全局搜索 / 会话导出
3. 长会话虚拟滚动
4. 工作流后续追问复用前序交接物的增量续跑
5. 模型选择真正随 ACP 会话下发（不再是纯展示）
6. SPRT 早停参数的真实流量标定（trace 采集 + 离线回放 + 阈值外置）
7. 非 Windows 平台的进程组整树终止

每批均执行 `npm run lint` + `npm run test:cogno`（涉及 Rust 时加 `cargo test` / `cargo check`，涉及构建时加 `npm run build`）并原子化提交。

## 3. 关键设计决策

### 3.1 反「伪兼容」数据治理

- `parseAcpConfigOptions`：缺失 `id`/`name`/`currentValue` 或类型非法的配置项直接丢弃，不猜测补位。
- 偏好模型 `modelId`：仅在运行时上报的模型选项 `value`/`name` 精确命中时下发；命中失败保持运行时默认并记录日志，不把任意字符串硬塞给 ACP。
- `acp_set_config_option`：拒绝运行时从未声明过的 `configId`。
- SPRT 阈值外置：白名单 + 数值区间 + 整数约束，非法字段剔除并显式 `console.warn`，不做字符串强转或旧字段回退。
- SPRT trace 阈值快照缺失时保持 `undefined`，回放直接报错，不以默认值冒充历史配置。

### 3.2 确定性回放

- 回放使用 `ignoreExternalThresholds: true`，并以 trace 内生效阈值（alpha/beta/sensitivity/中性基线/探索轮次/漏斗衰减/接地权重）显式重建参数。
- 同一输入与阈值下要求 `logLikelihoodRatio` 与 `decisionState` 逐位一致；不一致计入 `decisionMismatches` 且 CLI 以非零码退出。
- 已知边界：若未来 `stepSprtGovernor` 新增影响决策的观测维度而未写入 trace，回放会以 mismatch 暴露，不会静默漂移。

### 3.3 进程树终止安全性

- Unix SIGKILL 清扫安排在 `child.wait()` 之前：直接子进程此时仍以僵尸态占用 pid/pgid，进程组 ID 不会被内核回收复用，避免误杀无关进程。
- Windows 路径行为不变；两平台统一收敛到 `terminate_process_tree`。

## 5. 已明确未覆盖 / 遗留项

1. **模型选择器仅在「频道主消息流 / 私聊」会话键下展示**（与既有 usage chips 的 `activeThread.id::agentId` 键一致）；议题推演会话的 `roomId = topicId`，其配置项选择尚未接入议题抽屉。
2. **远程 WebSocket ACP 不参与 configOptions 采集**：远程通道按每次 prompt 建立连接，没有长驻会话可维护配置项。
3. **无真实 ACP 运行期 UI 自测**：模型选择器、usage chips、重试/导出按钮、虚拟滚动均仅完成类型/构建/自动化断言层验证，尚未在有真实 Agent 连接的桌面运行期逐项点击验证；符合「测试结论与报告真实性」要求，此处如实标注。
4. **SPRT 尚无真实流量样本**：采集与回放链路已就绪，但需要用户在实际推演中积累 trace 后运行 `npm run sprt:replay` 才能得到标定结论；尚未内置自动阈值搜索。
5. **Unix 进程组仅覆盖显式停止/重启/退出路径**：`kill_on_drop` 与应用崩溃场景仍只能终止直接子进程；孙进程依赖操作系统的孤儿回收。
6. **既有 Windows 环境测试失败**：`cargo test` 在默认系统临时目录下因沙箱权限失败；指向项目内临时目录后，仍有 5 条与本次改动无关的平台断言失败（附件路径分隔符 `/`、权限越界路径 `.codex/auth.json`、`~/` 解析），属于既有 Windows 兼容性问题，未在本轮修复。
